#Structure marks for nested combinable chains — Implementation Plan

RPI cycle: research thoughts/research/2026-10-11-1300-structure-marks-for-nested-combinable-chains.md (all file:line references trace there). Date 2026-10-11, HEAD 57e1e3dc, branch feature/composition-and-justification.

#Overview

Replace the Wikipedia ingest chain-demotion (nested b/strong i/em a chains collapse into generic-inline nodes) with a mark push: outer chain elements push non-intent tag-* structure marks (markSpecs carrying tag + attrs — real-world HTML semantics), the innermost element’s tag/attrs funnel onto the ONE composite generic-style intent per run (htmlTag/htmlAttrs). Motivation: generic-inline has no nodeSpecToTypeSpec link, so demoted chains attenuate typeSpec resolution toward the nearest registered ancestor — the same chain under different parents would need per-context typeSpec attachments. Marks attach to the text run’s parent context directly; no attachment bookkeeping.

#Decision Log (operator, 2026-10-11, one by one)

  1. Naming (Q1): tag-* family, canonical three only: tag-strong, tag-em, tag-a. Selectors route deprecated tags: b→tag-strong, i→tag-em (marks fully dynamic in state; small fidelity upgrade accepted). Extension (operator): unify — every combinable element pushes a structure mark and contributes to the intent; standalone elements render exactly as today; the existing strong/link style marks fold away; styling flows exclusively through intentStyleLinks; markStyleLinks stays as unused engine capability. Funnel (operator idea, adopted): the innermost element’s tag + attrs ride on the intent mark itself (htmlTag, htmlAttrs — the bag attr exists for exactly this), NOT on the edge (edges are static per intent name, innermost varies per run — combinatorial). Tag chain: attrs.htmlTag || edge.tag || "span" — htmlTag is the ingested truth, edge.tag the PM/menu fallback (“bold” menu intent → <strong>).
  2. Excludes policy (Q2): (a) reserved generic-style → group: "style", excludes: "style" (code — default-schema.ts:200). Intents stay mutually exclusive at the PM layer (Mark.addToSet); tag-* marks get no excludes/group declarations — PM defaults (own type only) give free coexistence with each other + exactly one intent. Ingest bypasses addToSet regardless.
  3. data-style-name on wrappers (Q3): (a) viewer sets data-style-name only on generic-style (intent) wrappers — it IS the intent’s identity and round-trip key. Structure wrappers render bare tag + bag; parse-back falls through the priority-60 catch-all to the per-tag rule ({tag: "em"} → declared attrs harvested). No bogus intent capture.
  4. Missing composite patches (Q4): (a) add "italic link" + "bold italic link" CompositeStylePatch entries + intentStyleLinks edges — extra, minimal, state-only commit before the engine switch (the <em><a> chain is the demo path; must style).
  5. Report (Q5): (5a) keep structure marks in markSets keys (honest provenance); (5b) add structureMarks: Record<string, number> counter per mark name.
  6. Same-type dedupe (Q6): (a) dedupe at push time — PM allows one mark per type per run anyway. Semantic note (operator): nested <em><em> is degree-of-emphasis HTML semantics, but hardly used and not representable in the PM mark model without node structures — accepted trade. (Plan note: the pop-last funnel in fact PRESERVES redundant same-type nesting: <em><em> renders <em><em data-style-name=…> — outer mark, inner intent. Only >1 same-type outer marks dedupe. Degree-of-emphasis via patch level (e.g. a future intensity intent) fits this design; out of scope.)
  7. Blast radius (Q7): (7a) fixture regenerates wholesale in the engine phase (same observable change, no extra commit); (7b) test rewrite = rewrite combineAs describe to marks assertions, keep demotionRules describe, fix the rest against the suite run (assert behavior, not implementation).

#Desired End State

<b>bold <i>x</i></b>                    <a href="./x">y</a>
run "bold ": [generic-style "bold", htmlTag b]            → <b data-style-name="bold">bold </b>
run "x":    [tag-b, generic-style "bold italic", htmlTag i] → <b data-mark-type="tag-b"><i data-style-name="bold italic">x</i></b>
standalone: [generic-style "link", htmlTag a, htmlAttrs href] → <a data-style-name="link" href="./x">y</a>
  • One style-resolving intent per run (contract kept by construction, now schema-enforced via group/excludes "style" at the PM layer).
  • Full HTML semantics reproduction (tags, nested order, href) with ZERO typeSpec attachment bookkeeping — text runs resolve in their parent’s context like plain runs.
  • Styling flows exclusively through intentStyleLinks + patches; markStyleLinks capability retained but unused by the Wikipedia state.

#What We’re NOT Doing

  • Variant B: multi style-links per run / live property merging (rejected — free combinations must stay impossible; constraints force typographic shape into StylePatches).
  • Per-parent/per-context typeSpec attachments for chain elements (obsoleted by design).
  • tag-b/tag-i marks (Q1-B: deprecated tags upgrade to canonical via selectors).
  • Degree-of-emphasis semantics for nested same-type emphasis (documented future idea).
  • npm run perf:composition / scripts/perf-composition — OFF LIMITS (operator rule 2026-10-06). Live checks use the puppeteer DEBUG harness only.
  • Style-menu/UI changes beyond what markSpec enumeration surfaces implicitly.

#The engine rule (the whole mechanism, for reference in Phase 3)

On descent, EVERY combinable element (mark/generic rule) does the same three things — no outer/innermost branching:

  1. push its structure MarkDesc (name = the rule’s mark name, e.g. tag-strong) onto the marks stack — declared attrs harvested per its markSpec (tag-a: href + bag), same-name dedupe (Q6);
  2. push its combineAs name onto the composite stack;
  3. record itself as the current funnel (el.tagName.toLowerCase() + its attrs bag).

At TEXT_NODE: pop the LAST structure mark (it is the innermost element for this run), funnel its tag/attrs onto the ONE intent mark:

const emittedMarks = [...marks]; // outer→inner
const intentName = [...new Set(composite)].sort().join(" "); // as today
const funnel = /* current innermost source element */;
if (emittedMarks.at(-1)?.kind === "mark") emittedMarks.pop(); // innermost → intent
emittedMarks.push({
    kind: "style", styleName: intentName,
    htmlTag: funnel.tag, htmlAttrs: funnel.attrs, // NEW: funneled onto the intent
});
count(report.markSets, markSetKey(emittedMarks)); // Q5a: structure names stay

hasCombinableDescendant (:621-651) and the composite.length > 0 || … chain condition (:965-970) delete entirely. Per-run funnel correctness falls out: each descent into a sibling text sets the funnel to ITS innermost element (<b>bold <i>x</i></b>: run "bold " carries htmlTag "b", run “x” carries tag-b + intent htmlTag "i"). Standalone elements: push+pop → NO structure wrapper, intent carries their tag/attrs → renders exactly as today. Same-type nesting (<em><em>): the popped innermost renders via the intent’s htmlTag, outer tag-em stays → redundant nesting preserved.

#Live-verification findings (two real defects caught, both fixed in

derivations.mjs, documented for the record):

  1. Stale descriptor state in getWrapMarks (caught as 25 CONTRACT VIOLATIONs on the <i><a> chains): kind/styleLinkName/ styleLinkType/styleName were declared once OUTSIDE the per-mark loop and never reset — the empty-patch guard (operator’s markStyleLinks declarations) left styleName at the previous mark’s value, so tag-em descriptors leaked the innermost intent’s “italic link” and resolved their registered id. Root fix: reset the four fields per mark — each mark derives ONLY from itself — plus full inertness for empty-patch declarations (no styleLinkName either: structure wrappers get no styler at all).
  2. Intent htmlAttrs bag never replayed (caught as href-less link wrappers): the intent branch probed "htmlAttrs" in defaultSchemaSpec.marks["generic-style"] — the SPEC TOP LEVEL, not .attrs — always false, a pre-existing bug made visible by unification (previously only lang rode intent bags, and lang is styler-owned — the styler re-wrote it; links carried href as the mark’s declared attr via the working mark branch). Fix: probe .attrs (also correct for a compiled MarkType).
