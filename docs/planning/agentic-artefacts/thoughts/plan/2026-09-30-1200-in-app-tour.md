# In-app tour for the Shell app (issue #134)

## Context
The legacy Video Proof app had a first-visit tour ([lib/js/legacy/user-guide.js](lib/js/legacy/user-guide.js)) built on a vendored intro.js 2.9.3, pointing at Video Proof-only element IDs (`#select-font-container`, `#keyframes-display-container`, …). The new `shell.html` app hosts many layouts (Motion Stage, Video Proof, Grid, Ramp, Type Stage, …) and has no onboarding. Goal: a ≤6-step tour that anchors only on shell chrome that exists for **every** layout, auto-shown once, re-openable from the Help menu.

## Library decision: reuse the vendored intro.js
- The first implementation used **driver.js** (MIT), because intro.js is licensed **AGPL-3.0** with a paid license for commercial use. TypeRoof won't be a commercial product, so that's no concern: driver.js was uninstalled and the tour uses the intro.js 2.9.3 that is already vendored as the `lib/js/vendor/intro.js` git submodule (no new dependency).
- intro.js 2.9.3 is a UMD script. Bundled by Vite/Rolldown it's treated as CommonJS (default export), served as a plain ES module (dev server, Vitest) it sets `window.introJs`; `app-tour.mjs` handles both.
- `introjs.css` contains IE hacks (`*display`, `filter: alpha(…)`) that Lightning CSS rejects at build time, so it is imported with `?raw` and injected as a `<style>` at the start of `<head>` when the tour starts (browsers ignore the hacks). `app-tour.css` comes after it and overrides it.
- intro.js, `introjs.css` and `app-tour.css` are **lazy loaded** (dynamic `import()`), once, the first time the tour is shown, so they're not fetched for returning visitors. A failed load resets the cached promise so that a later attempt can retry.
- 2.9.3 has no step titles: the title is rendered as `<h3 class="app-tour-title">` in the step's `intro` HTML.

## Tour steps (6, layout-agnostic)
Anchors come from [zones.typeroof.jsx](lib/js/zones.typeroof.jsx), [main-ui.mjs](lib/js/components/main-ui.mjs), [app-menu.typeroof.jsx](lib/js/components/app-menu.typeroof.jsx), [font-loading.mjs](lib/js/components/font-loading.mjs):

| # | Anchor | Content |
|---|---|---|
| 1 | none (modal) | Welcome to TypeRoof: proofing/animating variable fonts. |
| 2 | `.ui_layout_select` | Pick a layout; each one is a different proofing tool. The sidebar and stage adapt to it. |
| 3 | `.ui_font-select` | Pick a font. Add your own via **File › Manage fonts…** (TTF/OTF/WOFF/WOFF2). |
| 4 | `.typeroof-ui_sidebar` (side: right) | The settings for the active layout live here, below the layout/font selectors, including the playback controls of animated layouts. Comments sit at the bottom. |
| 5 | `.typeroof-main` (side: left) | The stage where the proof renders. (A dynamic hint about controls in `.typeroof-layout-before` was dropped during implementation: that zone holds different things per layout, e.g. Video Proof shows axis parameters there, and playback controls live in the sidebar.) |
| 6 | `.typeroof-app-menu` (side: bottom) | File: save/load state, copy share link, reset. Help: docs, and **Take the tour** to see this again. |

Rules: steps are not filtered. Each selector is resolved with `document.querySelector` when the tour starts (after intro.js has loaded, as the UI may have changed meanwhile); a missing element resolves to `null`, which intro.js shows as a centered dialog, like step 1. Keep the text in one `TOUR_STEPS` array so it's easy to edit.

## Implementation
1. **Dependency:** none, the vendored intro.js submodule (see above).
2. **New module** `lib/js/components/app-tour.mjs`:
   - `loadIntroJs()`: lazy loads `import('../vendor/intro.js/intro.js')`, `import('../vendor/intro.js/introjs.css?raw')` and `import('./app-tour.css')` once (see above); `injectIntroJsCss(document, css)` adds the intro.js `<style data-introjs>` once.
   - `TOUR_STEPS`, `getTourSteps(document)`, `hasViewedTour(window)`, `setTourViewed(window)`: localStorage key `typeroof-tour` = `viewed`, wrapped in try/catch with a cookie fallback (same approach as the legacy `viewedAlready`/`setViewed`).
   - `async startTour(domTool, {force=false}={})`: resolves to `null` if already viewed and not forced. Otherwise it loads intro.js, resolves the steps, then calls `introJs().setOptions({steps, …}).start()` with `showStepNumbers: false`, `skipLabel: 'Close'`, `hidePrev`/`hideNext: true` and `scrollToElement: false` (the sidebar is taller than the viewport), and resolves to the intro.js instance. Mark the tour as viewed when it is **closed** (not when it starts), so a reload mid-tour shows it again, via `onexit` (called for Close, Done, Escape and overlay click).
3. **Help menu entry** in [app-menu.typeroof.jsx](lib/js/components/app-menu.typeroof.jsx#L149): add a **Take the tour** `<li><button>` (followed by an `<hr />`) at the top of the Help `<menu>`. Its handler `_onClickTakeTheTour()` first closes all open menus, so they don't cover `.typeroof-app-menu`, then calls `startTour(this._domTool, {force: true})`.
4. **Auto-start**: `ShellController` is also used by the player and wikipedia apps, so [shell.mjs](lib/js/shell.mjs) only calls an optional `APP.onAppReady({domTool, uiFlags, isEmbedded})` hook at the end of `_allInitialResourcesLoaded`. [main-shell.mjs](lib/js/main-shell.mjs) passes `autoStartTour` from `app-tour.mjs`, which:
   - skips when embedded (`adapterWindow !== null`, i.e. opener/iframe) or when the `autoplay`/`autopause` flags are set (presentation use).
   - adds a `tour` hash flag (`#[tour]`) that forces it, the replacement for legacy `#view-intro`. It doesn't override the embedded/playback-flag skip.
   - defers with `requestAnimationFrame`, so the layout's widgets are in the DOM before measuring.
5. **Styling** `lib/js/components/app-tour.css`: port the helper-layer fix of the legacy [user-guide.css](lib/css/videoproof/user-guide.css) (the 2.9.3 helper layer obscures the highlighted element) and theme `.introjs-tooltip` with the shell tokens from [variables.css](lib/css/shell/variables.css) (font, colors, button style). Keep it minimal.
6. **Docs:** a short note in [docs/index.md](docs/index.md) (Shell section) about the tour, `#[tour]`, Help › Take the tour, and when it doesn't auto-start.

## Verification
- `npm run lint`, `npm run typecheck`, `npm test`.
- Unit test (`app-tour.test.mjs`, jsdom/vitest): there are always ≤6 steps and they all resolve against the shell chrome; the viewed flag round-trips and falls back to a cookie when localStorage throws; `startTour` doesn't start when viewed unless forced, and marks the tour viewed on exit; `autoStartTour` schedules the tour by default, skips when embedded or with `autoplay`/`autopause`, is forced by `tour`, and `tour` doesn't override the skip.
- Manual, `npm run dev:app` → `shell.html`: clear localStorage and check that the tour auto-starts; step through it in **each** layout (switch the layout, then Help › Take the tour) and check that every popover anchors correctly; check that it doesn't auto-start on reload, that `#[tour]` forces it, and that it doesn't auto-start with `#[autoplay]`.
- `npm run build:serve`: check that the tour works in the production bundle (CSS included).
