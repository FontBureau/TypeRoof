#Approach (a) — Font-size re-basing & Node Style Links: Implementation Plan

#Overview

Per ROADMAP approach (a) + the 2026-10-12 design conversation: (1) relativeFontSize becomes a unit-carrying {value, unit} pair (plain numbers migrate as baseEm, non-breaking); (2) em unit semantics resolve in the MERGE channel (createPatched) against the origin typeSpec’s outbound effective font-size — the true relative basis for style patches and marks; (3) inline nodes become a third style-link family inlineNodesStyleLinks, routed to UIDocumentStyleStyler (the mark styler) in both renderers, on a single-element inline DOM. Approach (b) composition threading is already implemented (6dbbf38e).

#Current State Analysis

  • fontSize is purely synthetic (baseFontSize × relativeFontSize, properties-generators.mjs:209-244); every consumer receives the pre-flattened number; nothing strips units (research §1).
  • Patch scopes have no parent (baseFontSize falls to the model default 12): patches resolve against the ROOT base — the “bold: 2 → 28pt instead of 36pt” defect (live-properties.typeroof.jsx:225-344, in-test documentation index.test.mjs:984-988; research §2).
  • The merge channel already carries the needed basis: PatchedScopeProperties “parent” layer = origin outbound effective map incl. resolved generic/fontSize (scope-resolution.mjs:370-414, :462-483) — what measurement reads (composition-controller.ts:913-933).
  • Inline nodes style exclusively via UIDocumentTypeSpecStyler (full block write set) with the root-fallback font basis (integration.typeroof.jsx:226-231); no inline branch exists anywhere in the stylers (research §2, task 2026-10-12 #11).
  • The style-link pipeline is family-parametric except at enumeration points (TypeSpecModel fields, styleLinksGen list, StyleLinksMeta instantiations, pps-maps/defaults lists, editor ternaries, UI classes) — task 2026-10-12 #10 §4.

#Desired End State

  • State authors write relativeFontSize as {value, unit} — units: baseEm (default; today’s semantics), em (relative to the containing context’s effective size), absolute (pt…). Existing plain-number states parse unchanged as baseEm.
  • A style patch with em composes against the containing typeSpec’s effective size (li 18pt × 2 = 36pt) in the SAME merged scope measurement reads — rendered and measured bases agree.
  • An inline node styles like a mark: via an inlineNodesStyleLinks edge to a style patch, applied by UIDocumentStyleStyler on its single element; without an edge it INHERITS the containing context (no explicit font-size write — today’s root-fallback 14pt write disappears; roadmap observation 3 fixed).
  • Block nodes: zero behavior change (a1 realized by routing, not by branching; UIDocumentTypeSpecStyler serves blocks only; baseFontSize semantics untouched).
  • Per-phase verification: npm run typecheck, npm run lint, vitest, puppeteer DEBUG harness (scripts/debug-with-puppeteer.mjs + scripts/puppeteer-probes/). npm run perf:composition OFF-LIMITS.

#Key Discoveries (load-bearing facts)

  • Pair precedent (re-use per operator): InlineLengthValueModel struct + unitValuePairCoherenceFn + UnitModel.enumItems unit select — type-spec/horizontal-layout-models.mjs:16-36, length-models.mjs:56-71; pair defaults deserialization defaults.mjs:199-215; pair generator transport _inlineLengthGen properties-generators.mjs:482-497 (task #8).
  • PM natively supports contentDOM === dom (top doc desc + ALL marks — prosemirror-view dist :1519, :1234) and wholesale-removes non-desc children of contentDOM on sync (:1646-1662): single-element views must keep host children EMPTY — outfitter widgets already gate on outer !== inner and stay inactive (task #12).
  • UIDocumentStyleStyler write surface = the a1 target surface exactly (font-family, font-size, features/variations, colors, direction, lang — type-spec.typeroof.jsx:1008-1100; NO width/text-align/ margins/columns) (task #11).
  • Dep-resolution shadowing trap: a synthetic dep on generic/fontSize resolves LOCALLY first (scope-resolution.mjs:295-303) — the em basis must NOT be threaded as a dep on that name into a scope that yields its own fontSize synthetic; the merge boundary (origin outbound) is the clean basis source (task #9).
  • getWrapMarks is mark-list-only (derivations.mjs:412+536); composition _resolveLeafStyleLink (composition-controller.ts:636-678) resolves leaves against mark descriptors only — nested leaves under inline nodes need an explicit resolution extension (phase 6).
  • Editor DOM split consumers: only 2 CSS selectors + the probe helper (querySelector ?? el, already tolerant) — type-stage.css:157-160 (box-sizing; viewer parity :220-223 puts it on *[data-node-type] directly), line-spans.css:81 (textblocks only — unaffected), editor-dom.mjs:65/:90 (task #13).

#What We’re NOT Doing

  • NO α: no typeSpec-channel parent-basis synthetics; block font-size semantics unchanged (operator 2026-10-12: generic/fontSize is already the true em value — a parallel parent synthetic would fork the basis).
  • NO baseFontSize change (kept as feature: mid-tree sub-document re-anchoring); NO key rename (relativeFontSize stays).
  • NO inline-block / width path for inline atoms (a1 unconditional).
  • NO UIDocumentTypeSpecStyler.update restructure or inline branch — superseded by routing (inline elements stop reaching it).
  • NO composition geometry changes (the controller measures correctly; only leaf basis threading, phase 6).
  • NO perf-composition runs; NO resolution machinery keyed on node kinds (units carry intent — convention over machinery).

#Implementation Approach

Six phases, marks/patches FIRST (operator: inline handling last, so marks/patches are verified working before node routing):

  1. Pair form (non-breaking) → 2. merge-channel em (patches/marks fixed; live checkpoint) → 3. one-element inline DOM (PM-contract change, probe-gated) → 4. inlineNodesStyleLinks + routing to the mark styler → 5. “Node Style Links” UI wiring → 6. composition basis threading + QA + state re-tuning.

Each phase ends with the verification battery + proposed commit; pauses for operator confirmation (RPI protocol). Tests assert behavior (inputs → observable outcomes), not implementations.
