#Per-Entry keyMoments Ownership (Videoproof) Implementation Plan

#Overview

Make keyMoments ownership per-entry and explicit in the videoproof layout: keyMoments[0] is the property-setting keyMoment (user data, serialized); keyMoments[1..n] are animation-driving keyMoments (generated by axesMath, marked GENERATED_DATA per entry, never serialized, regenerated on load). This ends silent data loss and file bloat caused by list-level GENERATED_DATA markers being lost on user edits, without moving any fields or UI and without affecting motion-stage (which shares the actor models and never marks entries).

Research: thoughts/research/2026-08-12-1040-keymoments-ownership.md Design decision “Option D” approved by operator 2026-08-12.

#Current State Analysis

  • applyAxesMathLocations (lib/js/components/axes-math.mjs:432-505) generates the V2 actor’s keyMoments (27 entries) and each cell’s keyMoments (1 entry), marking BOTH LISTS with keyMoments[GENERATED_DATA] = 'axesMath' (:495, :503).
  • The marker is an own symbol property on the list instance; it survives freezing (list-model.ts:267-310) but is lost whenever a user edit creates a new immutable (getDraft(), base-model.ts:359-370, constructors never copy symbol properties). Consequences today:
    • Edit charGroup on keyMoments[0] → marker lost → all 27 generated entries serialize (file bloat; observed in downloads/typeroof-20260811-150038.Videoproof.json).
    • Then change axesMath → regeneration re-marks the list → the edit survives live but is no longer serialized → silent data loss on next save/load.
  • _updateKeyMomentsAxesLocationsFromLocations (axes-math.mjs:400-429) already treats entry 0 specially: it reuses the entry-0 draft because “the first moment contains actor specific settings” (:407-409).
  • Every videoproof UI binding targets keyMoments/0 fields (videoproof.typeroof.jsx:2097-2320; _getDefaults hardcodes activeKey = "0" at :2394-2398). No keyMoments list editing UI exists in videoproof; the only list consumers (renderer, UIAxesMath) are read-only.
  • Serialization: _serializeContainer (base-model.ts:645-707) checks _skipSerialize per child (:657-660) and writes null placeholders for empty children in lists to preserve positions (:680-700). null entries deserialize back into primal entries (list-model.ts:190-203).
  • Cell keyMoments are auto-created when missing by initCellKeyMoments (videoproof.typeroof.jsx:1234-1278, commit ca1ed19d) and currently marked GENERATED_DATA (:1276).
  • Motion-stage edits the same models via generic machinery (motion-stage.mjs:1139-1314), never calls applyAxesMathLocations, never sets GENERATED_DATA markers.

#Desired End State

  • Saving a videoproof state serializes only keyMoments[0] per keyMoments list (with its user-set fields, e.g. charGroup); generated entries 1+ never appear in state files.
  • Loading a videoproof state regenerates entries 1+ from axesMath, preserving entry 0 and all its user-set fields, in any order of prior edits (charGroup edit → axesMath change → save → load loses nothing).
  • Cell keyMoments[0] is auto-created when missing and treated as user data: edits serialize and survive round-trips and axesMath changes.
  • Legacy state files (with fully serialized, unmarked animation keyMoments) load correctly: entry 0 lifted as user data, entries 1+ regenerated, a console.warn documents the migration.
  • Motion-stage behavior is unchanged: unmarked keyMoments lists serialize fully with positions preserved.

#Key Discoveries:

  • axes-math.mjs:407-409 — entry 0 is already the designated “actor specific settings” holder in generation code.
  • base-model.ts:657-660 — the serializer checks the marker per list child, so per-entry marking needs no metamodel changes.
  • list-model.ts:190-203 — null serialized entries deserialize as primal entries; entry-0-only files round-trip cleanly.
  • videoproof-array.mjs:399 — V2 reuses V1’s VideoproofArrayKeyMomentsModel; serialization policy must therefore trigger only on marked instances (motion-stage/V1 never mark → unaffected).
  • presets.mjs:27-110 — existing marker-stripping/checking patterns (copyToDraft, Object.hasOwn(unwrapped, GENERATED_DATA)).

#What We’re NOT Doing

  • No moving of fields or UI to the root layer actor; no new properties UI.
  • No change to stageBackgroundColor (inherit:false is intentional — re-painting would occlude underlying actors).
  • No unconditional regeneration (the looksLikeNew heuristic stays; it is reliable again under per-entry ownership). May be revisited later.
  • No metamodel changes (marker, serializer, comparison all stay as-is).
  • No cross-layout copy/paste (future intent; stripping TODOs already committed, 45d62326).
  • No UI rework for inherited-value display (Q4: accepted, separate effort).

#Implementation Approach

Ownership becomes per-entry: generation marks entries 1+ (never entry 0), and the two keyMoments list models get a small [SERIALIZE] override that omits marked entries without writing null placeholders (position-safe because marked entries are always a generated suffix, and only ever produced by videoproof’s generation). Entry 0 keeps serializing as a normal user-data entry (its generated axesLocations/label included — documented, harmless redundancy, overwritten on regeneration). Legacy files are migrated by the load-time coherence chain, the idiomatic hook already used by initCellKeyMoments.

Process per phase: implement → behavior tests green → full suite + typecheck + prettier/eslint → STOP and present the commit message for review → commit only after operator approval. Commit messages carry the standard metadata trailer (model/provider/agent).

#Phase 1: Per-entry generated marking + serialization policy

#Overview

Switch generation from list-level to per-entry marking and teach the two keyMoments list models to omit marked entries when serializing.

#Changes Required:

#1. Mark entries 1+ instead of the list

File: lib/js/components/axes-math.mjs Changes: In _updateKeyMomentsAxesLocationsFromLocations (:400-429), after building newKeyMoments, mark every entry except index 0 with GENERATED_DATA on the entry drafts. Remove both list-level keyMoments[GENERATED_DATA] = 'axesMath' statements in applyAxesMathLocations (:495, :503) and keep/adapt the NOTE comment (cross-layout stripping now applies to entry markers).

// in _updateKeyMomentsAxesLocationsFromLocations, before keyMoments.splice:
// Entry 0 is the property-setting keyMoment (user data, serialized).
// Entries 1+ are animation-driving, generated from axesMath; they are
// marked so serialization omits them and load regenerates them.
for (const keyMoment of newKeyMoments.slice(1))
    keyMoment[GENERATED_DATA] = "axesMath";

Cell keyMoments (single entry 0 via resetLocations) are thereby never marked — they become plain user data.

#2. Omit marked entries when serializing

File: lib/js/components/actors/videoproof-array.mjs Changes: Give VideoproofArrayKeyMomentsModel (:106) and VideoproofArrayV2CellKeyMomentsModel (:378) a [SERIALIZE] override (via subclassing the createClass result) that skips children carrying GENERATED_DATA and otherwise behaves like _serializeContainer for lists (null placeholders for empty user entries, null for an empty result). Only marked instances change behavior; unmarked (motion-stage, V1, dev layouts) serialize exactly as before.

#Testing Strategy

Behavior tests (serialize → deserialize round-trips through the real models, asserting observable outcomes — not internal functions), extending lib/js/components/layouts/videoproof-cell-keymoments.test.mjs or a sibling videoproof-keymoments-ownership.test.mjs reusing its font-stub scaffolding:

  1. Round-trip preserves user edit: primal state → set charGroup on V2 keyMoments[0] → serialize → payload has exactly one keyMoments entry and it contains charGroup → deserialize → 27 keyMoments present, entry 0 has the charGroup, entries 1+ carry GENERATED_DATA markers.
  2. No data loss across regeneration: after the charGroup edit, change axesMath (force updateRap regeneration) → serialize → entry 0 still has charGroup → deserialize → charGroup intact.
  3. Motion-stage guard: an unmarked keyMoments list (as motion-stage owns them) serializes all entries with positions preserved (null placeholders for empty entries kept).
  4. Cell edit round-trip: set a cell keyMoments[0] property (e.g. textColor) → serialize → cell keyMoments present with the value → deserialize → value intact.
  5. Untouched cell invariant: fresh state round-trip → cell keyMoments[0] exists after load (regression guard for ca1ed19d).
  6. Legacy migration: payload shaped like downloads/typeroof-20260811-150038.Videoproof.json (27 unmarked entries, charGroup on entry 0) → load → entry 0 charGroup preserved, entries 1+ regenerated and marked, migration warning issued.

Unit-test style is the existing vitest setup (lib/js/**/*.test.mjs).
