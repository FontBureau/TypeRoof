#Research: Mark machinery as-is — structure marks for nested combinable chains

#Research Question

Formal RPI cycle (operator 2026-10-11, /research_codebase). Context: Wikipedia ingest collapses nested combinable mark elements (b/strong, i/em, a) — bc48fdb9 (composite intents + generic-inline demotion), 57e1e3dc (selector-matched demotionRules), b3d53d5b (textless-mark demotion). Problem: generic-inline has no nodeSpecToTypeSpec link, so demoted chains attenuate typeSpec resolution toward the nearest registered ancestor; the same chain under different parents (h1 vs paragraph vs figcaption) would need per-context typeSpec attachments — combinatorial. Operator decision: Variant A — the chain demotion becomes a MARK push: new NON-INTENT “structure marks” (markSpecs carrying tag + attrs, reproducing real-world HTML semantics) on the text-run marks stack; the ONE composite generic-style intent stays the sole style-resolving mark per run; textless demotion (demotionRules) stays; free mark combinations stay forbidden — the exclusivity contract forces typographic shape through StylePatches. Variant B (more than one style link per run, merged live properties) is rejected. This document maps the machinery AS IT IS; it does not design the change.

#Summary

  • The structure-mark pipeline exists end-to-end, unused: a markSpec with tag + attrs and no markStyleLinks edge renders plain tag + attrs, no styler (findings 3, 7).
  • The typeSpec problem is confirmed: generic-inline is absent from nodeSpecToTypeSpec; demoted wrappers attenuate resolution to the nearest registered ancestor, and measurement (textblock scope) vs viewer (leaf context) converge only because the attenuation lands at the textblock’s own resolution today (finding 4).
  • Exclusivity lives in two places: generic-style excludes “_” (ALL marks), enforced only at the ProseMirror layer (Mark.addToSet); ingest writes marks directly and bypasses it. State markSpecs strong/link declare neither excludes nor group (finding 7).
  • Composite intents are the single style resolver per run: pushed last (innermost wrapper), dedupe/sort/join at TEXT_NODE; “italic link”/“bold italic link” have no style patch yet (findings 1, 6).
  • Change coupling: state JSON + ingest.ts + ingest.test.mjs + regenerated replacement-state fixture travel in ONE commit (finding 8).

#4. Type-spec resolution and the generic-inline attenuation (the problem)

  • pathOfTypes = root->node typeKeys (derivations.mjs :274, threaded via childrenContext :277-289); the text-run context excludes the own “text” (document-nodes-meta/index.mjs :1210-1212).
  • getTypeSpecPropertiesIdMethod (integration :190-286): last typeKey -> nodeSpecToTypeSpec.get(typeKey).link; absolute “/” = origin-anchored, “./” / bare = parent-anchored (recursive on the parent chain; explicit hits skip excludeFromFallback); empty/absent link -> _getBestTypeSpecPropertiesId (:113-170) walks testPath.slice(0, -2) toward root until a registered typeSpecProperties@ id is found.
  • Case 1 — text with marks directly in paragraph/h1: the parent typeKey IS linked (heading-1 -> /headings/h1) -> marks resolve at the heading typeSpec.
  • Case 2 — text inside demoted generic-inline wrappers: generic-inline ABSENT from nodeSpecToTypeSpec (state JSON :893-985, verified) -> typeSpecLink = "" -> the fallback walk skips every generic-inline level to the nearest registered ancestor. The wrappers attenuate; per-context typeSpec attachments (a child typeSpec per parent) would be needed to give them specs — the combinatorial problem.
  • Divergence surface: composition measures with the TEXTBLOCK scope (_styleResolutionContext, index.mjs :901-911, on the parent element) while the viewer renders with the LEAF context (incl. the wrappers, viewer :981-990) — both converge today only because the attenuation lands at the textblock’s own resolution.

#5. Composition controller and the exclusivity contract (text-composition/composition-controller.ts)

  • _buildInlineItems :568-620 walks the textblock inline content: text -> leaf with styleLinkPropertiesId = _resolveLeafStyleLink(...); generic-inline children recurse as inlineContainer; contentless children are inlineAtom with a null leaf.
  • _resolveLeafStyleLink :635-684: skips descriptors with styleLinkName == null || styleName == null (:657-661), collects getStyleLinkPropertiesId(...) ids for the rest; ids.length > 1 -> console.error("CONTRACT VIOLATION ... style links are EXCLUSIVE (styleLinkProperties@ is the full story) ... using the innermost.") (:674-681). This guard is why bc48fdb9 collapses chains into ONE composite intent instead of stacking strong + link marks.
  • Resolved ids feed per-run measurement (font, axes, features, language, direction, fontSize) from the registered styleLinkProperties@ entry, textblock style as fallback (:887-930, :1150-1172).

#7. ProseMirror mark-set semantics — where exclusivity is enforced

  • Mark.addToSet (prosemirror-model/src/mark.ts :24-47): same-type mark replaced (this.eq(other)); a mark whose type the EXISTING set excludes is NOT added. MarkType.compile (prosemirror-model/src/schema.ts :621-624): excludes "_" -> excluded = ALL mark types.
  • Consequence: generic-style cannot coexist with ANY mark at the PM layer — in PM editor-mode mutations, adding generic-style evicts every other mark, and adding another mark onto a run carrying generic-style is rejected. The INGEST path bypasses this: ingest writes the document marks list directly; only PM-schema edits normalize through addToSet.
  • State markSpecs strong/link declare neither excludes nor group today — default: each excludes only itself, so they coexist freely with each other (and with new structure marks) at the PM layer.

#Open Questions

(To resolve in /create_plan; operator calls marked.)

  1. Structure-mark naming — strong/link are taken as style marks; kebab-case; names surface raw in mark_spec-manager. Candidates: tag-strong/tag-em/tag-a, html-, struct-. OPERATOR.
  2. Excludes policy encoding — generic-style excludes “_” (reserved, default-schema.ts :200) evicts ALL marks at the PM layer; structure marks must coexist with the composite generic-style per run. Narrowing to group “style” / excludes “style” touches the RESERVED schema (code); state markSpecs carry excludes/group through the 1:1 copy (integration :884-892). Where is “structure marks never style-resolve” encoded — schema-level excludes/group, ingest-only construction, or both?
  3. data-style-name on structure wrappers — styleLinkName defaults to markType for markSpec marks (derivations :490), so structure wrappers would carry data-style-name: cosmetic noise AND a parse-back hazard vs the priority-60 generic-style catch-all (default-schema :207-230). Decide: emit data-style-name only on style-resolving (intent) wrappers, or structure markSpecs opt out.
  4. Missing composite patches — “italic link” / “bold italic link” intents are emitted but have no stylePatchesSource entry. Add CompositeStylePatches in the state now or declare the gap?
  5. markSets report semantics — markSetKey (ingest :498-504) will include structure-mark names in run keys; existing assertions shift. Also: own report counter for structure marks (per-tag inlineNodes is the model) or none?
  6. Same-type structure marks — PM allows one mark per type per run (same-type replaced, mark.ts :24-47); nested same-tag chains () dedupe to one structure mark — ingest-side dedupe policy.
  7. Fixture + test blast radius — regenerate the replacement-state fixture + rewrite the combineAs describe; confirm no other test asserts generic-inline demotion.
