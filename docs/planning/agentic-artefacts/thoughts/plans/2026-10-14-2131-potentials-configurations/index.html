#Named Justification-Potentials Configurations — Implementation Plan

status: concluded (2026-10-16 15:43, operator “wrap it up now”)

date: 2026-10-14T21:31:00+02:00 research: thoughts/research/2026-10-14-1810-potentials-configurations.md branch: feature/composition-and-justification

#Overview

Selectable justification potentials for BOTH greedy-fit and knuth-plass: potentials = “auto” (today’s best-fit discovery) or a named configuration (first: the headline wdth-narrowing tables, folded from the varla-varfo WDTH_JUSTIFICATION_SPECS stub into the unified potentials structure with a real dflt slot). Named selection is maximally graceful: no family/axis gating, missing navigation dimensions filled from table-declared defaultLocations or manual overrides, treated axes the font lacks applied anyway (no-ops). The treatment config generalizes: ONE toggle surface for axis tags and the pseudo-axes tracking/wordspace. Anchoring becomes a triple option (run / font / off).

#Desired End State

  1. potentials selectable per typeSpec on both greedy-fit and knuth-plass: “auto” (default, behavior byte-identical to today) or one of robotoFlexText / robotoFlexHeadline / amstelvarText / amstelvarHeadline.
  2. Headline tables carry the stub semantics: natural state = the WIDE end (wdth 151 / 125), narrowing-only by construction: { wdth: [35, 151, 151] } / { wdth: [50, 125, 125] }, flat leaves, provenance comments incl. the widening FIXME.
  3. PotentialsTable.defaultLocations (parallel to dimensions): missing navigation dimensions resolve from it; manual overrides (ordered map tag -> number, fill-only) take precedence.
  4. potentialsAnchoring: “run” (default, status quo: dflt := the run’s resolved value, step 0 = no change) | “font” (the WHOLE resolution — leaf navigation AND anchoring — at the font’s default location: one stable anchor per font, shared by all runs) | “off” (navigate at the run’s location, apply the authored triple verbatim — the configuration asserts its natural state).
  5. treatments: list of DISABLED treatment tags (axis tags + the pseudo-axes tracking/wordspace); set semantics, coherence dedupes and prunes entries not offered by the selected NAMED configuration (auto is font-dependent: no pruning there; unknown tags ignored gracefully at resolution). Empty list = all on.
  6. The generated selection doc string (“the potential is selected by: opsz(14), wght(400), wdth(100)”) travels with the payload.
  7. No changes to the pure algorithms; no migration for dropped struct fields (in-repo documents are updated directly; a deserialization check documents that unknown fields drop silently).

#What We’re NOT Doing

  • Editable/document-scoped potentials storage + metamodel (stays code-level; the ROADMAP’s open deferred item).
  • Advanced selection schemes (family + useCase auto-selection).
  • KP treatment/anchoring UI beyond the three shared fields (KP keeps planner defaults for treatments; exposing the list later is trivial).
  • Per-treatment impact weights / ordering; inter-line harmonization.
  • Any migration code for treatmentXTRA/treatmentTracking/ treatmentWordspace.
  • Perf harness (OFF LIMITS per operator rule 2026-10-06).

#Implementation Approach

Bottom-up in dependency order: data + resolution, planner config, metamodel/UI, controller wiring — each phase independently verifiable (the algorithm contract stays pure throughout). The five design picks settled with the operator: clean ordered map for overrides; validated StringModel items for the treatments list; doc string in the payload; anchoring governs auto AND named (default “run” = status quo); “font” mode resolves leaf AND anchor at the font defaults.

#Post-plan addendum 4: QA round 2026-10-16 14:05-14:35

Operator smell: KP h1 “The Universe Next Door” — the middle line (“verse Next”, wdth 76.77) did not fill the 10cm measure though polish is on. The composed spans render white-space: nowrap (line-spans.css, overriding PM’s vendor break-spaces — verified empirically in-page), and nowrap COLLAPSES runs of collapsible whitespace to one space, while HarfBuzz shaped every character. The operator’s text had a double space; the ingest (ingest.ts:818) leaves HTML indentation after replacing newlines — every pretty-printed source ingests ~13-space runs. ALL ingested documents with formatted HTML were affected.

  • segmenter.ts: a whitespace RUN is ONE segment (raw offsets preserved — the editor applicator maps segment.start/end directly to PM positions); a run containing \n is an explicit break.
  • composition-controller: segment texts shaped NORMALIZED (runs → one space; explicit [ \t\n\r\f\v] class — JS \s includes U+00A0 which must NOT collapse).
  • 3 hardcoded fixture break tables updated (they encoded the space-inflated measurements; e.g. t1 now 7 lines instead of 9).

Fix: line-first spans are display:block THEMSELVES (width: fit-content keeps the color-coding background hugging the text) — the ::before mechanism is gone; caret positions are ordinary block-start positions. Pinned by qa-m6-caret.mjs (ArrowRight lands exactly before “D”).

KP underfullTreatment removed (operator 13:55/14:05 decision: KP is not appropriate for headline treatment): the config field, the evaluateEdge marking (last-line + widening branches), the marker propagation, the polish skip, the struct field, generator list, controller resolution + ingredient, and the two test suites. underfullTreatment is greedy-fit-only now.
